## Overview

This case study documents an authorized TryHackMe SkyNet assessment. It is one of the stronger examples in the portfolio because the compromise developed across multiple trust boundaries rather than depending on a single isolated vulnerability.

The chain moved from exposed SMB information to valid credentials, authenticated web access, CMS vulnerability research, remote command execution, and finally a root-level scheduled-task abuse path.

## Scope and methodology

The target was an intentionally vulnerable TryHackMe lab. The assessment followed this sequence:

1. Service discovery
2. SMB and web enumeration
3. Sensitive-file and credential discovery
4. Authentication validation
5. CMS and application research
6. Remote file inclusion validation
7. Post-compromise enumeration
8. Scheduled-task / archive-job analysis
9. Privilege-escalation validation

## 1. Attack-surface mapping

Nmap identified HTTP and SMB services. Web directory enumeration exposed a SquirrelMail login interface, while SMB enumeration revealed accessible shares and files.

The important observation was that the SMB share exposed information that could influence authentication testing elsewhere in the environment.

## 2. Credential exposure through SMB

The accessible share contained an `attention.txt` file and a password list. Controlled credential testing against the discovered login functionality produced valid credentials.

After authentication, an email account exposed additional information that led to access to another SMB share belonging to the target user.

### Security impact

Sensitive files exposed through an unauthenticated or weakly protected network share can become an authentication bypass in practice when users or applications reuse the information elsewhere.

**Recommended controls:**

- Restrict SMB shares to the minimum required users.
- Review anonymous/guest access.
- Avoid storing passwords, password lists, or authentication hints in shared locations.
- Monitor unusual access to sensitive share contents.
- Enforce unique credentials and prevent password reuse.

## 3. CMS vulnerability research

Further enumeration identified an administrator path running Cupa CMS. Public vulnerability research indicated a remote file inclusion issue affecting the CMS.

Rather than treating a scanner result as sufficient evidence, the assessment validated the affected functionality in the authorized lab and confirmed that controlled remote content could reach the vulnerable include operation.

The resulting execution path provided a web-server shell.

### Security impact

Remote file inclusion can allow attacker-controlled content to be processed by the application and, depending on configuration, can lead to remote code execution.

**Recommended controls:**

- Keep CMS software and plugins patched.
- Disable dangerous dynamic inclusion patterns.
- Use strict allow-lists for local resources.
- Prevent outbound requests from application processes where unnecessary.
- Run web services with least privilege.

## 4. Post-compromise enumeration

After initial access, local enumeration identified a backup script under `/backups`. The script compressed the web root and was executed periodically with elevated privileges.

The key security issue was not the use of `tar` itself. It was the combination of a privileged scheduled task, attacker-influenced files in the archived directory, and unsafe handling of archive arguments.

## 5. Privilege escalation

The lab configuration allowed the archive job to interpret attacker-controlled filenames as options. This created a path to command execution in the privileged context.

The assessment validated the resulting root-level impact in the lab.

### Security impact

Privileged scheduled tasks that process attacker-controlled files can become a local privilege-escalation primitive.

**Recommended controls:**

- Never run backup jobs as root unless required.
- Use absolute paths for utilities and controlled working directories.
- Terminate option parsing where supported.
- Avoid processing attacker-writable directories from privileged jobs.
- Review scheduled tasks for unsafe interaction with user-controlled filenames.

## Assessment chain

**Exposed SMB data → credential discovery → authenticated access → CMS vulnerability → web-shell access → privileged scheduled task → root**

This is the main reason SkyNet is worth keeping in the flagship portfolio: it demonstrates the ability to correlate findings across network services, application functionality, credentials, and Linux privilege boundaries.

## What this exercise demonstrates

A mature assessment does not stop when the first vulnerability is found. Each stage should be used to understand the next trust boundary and determine whether separate weaknesses can be chained into a larger impact.

The strongest evidence in this assessment is therefore the attack chain itself—not simply obtaining the final flag.
