## Overview

This case study documents an authorized TryHackMe CMSpit lab assessment. The exercise demonstrates how several individually interesting weaknesses can form a complete attack chain: application enumeration, account and reset-token abuse, web-shell access, credential discovery, and an unsafe privileged utility.

## Scope and methodology

The target was an intentionally vulnerable lab. The assessment followed this sequence:

1. Service discovery
2. Web application identification
3. User and password-reset functionality analysis
4. Authentication impact validation
5. File-upload and command-execution testing
6. Local credential discovery
7. Privilege-boundary analysis
8. Evidence collection and reporting

## 1. Application discovery

Initial Nmap enumeration identified the exposed services. The HTTP service presented a CMS login interface, which became the primary application attack surface.

## 2. Account and reset-token testing

The application exposed user-related functionality that allowed account information and password-reset tokens to be queried. The important security issue was not simply that information was visible: the token could be used to change an account password and cross the intended authentication boundary.

The lab validation demonstrated successful login with the changed password.

### Security impact

A password-reset mechanism must ensure that reset tokens are unpredictable, scoped to the correct account, protected from disclosure, and invalidated after use. If an attacker can obtain or manipulate a valid reset token, the result can be account takeover.

## 3. Post-authentication command execution

After gaining access to the authenticated CMS functionality, the assessment identified file-upload behaviour. Controlled testing demonstrated that uploaded content could be used to obtain command execution in the lab environment.

This provided the foothold required for local enumeration.

## 4. Credential discovery and lateral movement

Local enumeration revealed a MongoDB instance containing credentials. Those credentials provided access to another user account through SSH, demonstrating how exposed application or service credentials can turn an application compromise into broader host access.

## 5. Privilege escalation

The `sudo -l` review showed that the discovered user could execute `exiftool` with elevated privileges without supplying the root password. The lab environment was deliberately configured around CVE-2021-22204 and the vulnerable utility.

The assessment validated the resulting privilege boundary and documented the root-access impact.

## Findings

### Finding 1 — Password-reset token exposure

**Impact:** account takeover within the vulnerable lab.

**Recommended controls:**

- Generate high-entropy, single-use reset tokens.
- Never expose reset tokens through unrelated user-data endpoints.
- Bind tokens to the intended account and reset operation.
- Expire and invalidate tokens after use.
- Avoid disclosing sensitive account data through enumeration endpoints.

### Finding 2 — Unsafe file-upload / command-execution path

**Impact:** authenticated command execution in the lab environment.

**Recommended controls:**

- Strictly validate uploads.
- Store uploads outside executable paths.
- Disable script execution where files are uploaded.
- Apply least privilege to application processes.

### Finding 3 — Privileged vulnerable utility

**Impact:** local privilege escalation in the vulnerable lab.

**Recommended controls:**

- Keep security-sensitive utilities patched.
- Minimize commands permitted through `sudo`.
- Review privileged execution paths regularly.
- Remove unnecessary elevated permissions.

## What this exercise demonstrates

This assessment is useful because it shows why penetration testing should follow the application's trust boundaries. An account-management flaw can become authenticated application access; application access can become command execution; command execution can expose credentials; and credentials can create a path to a privileged operating-system context.
